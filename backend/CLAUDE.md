# fastapi-template Backend — Hexagonal Architecture

REST API template. It ships the authentication slice end to end, plus a neutral example catalogue (`items`, `collections`, `tags`) that exists so the template has something to demonstrate and can be deleted from a generated project. `Item` is built end to end (domain, port, service, repository, schemas, router); `Collection` is still ORM-only (issue #37). This CLAUDE.md complements the monorepo root CLAUDE.md.

## Documentation

The documentation map lives in the monorepo root CLAUDE.md. Open only the document the current task calls for — never load them all.

## Stack

- Python 3.12
- FastAPI (async)
- SQLAlchemy 2.0 (async, declarative models)
- Alembic (autogenerated migrations)
- PostgreSQL 16, with no extensions. A catalogue search endpoint (`/items/search`) is a plain `ILIKE`, never a full-text index
- pytest + pytest-asyncio + httpx (testing)
- structlog (structured logging, wired — see `docs/backend-logging.md`)
- Ruff (linting + formatting)
- mypy strict (type checking)

## Hexagonal Architecture (Ports & Adapters)

This is the tree **as it stands today**, not an aspirational one. It is thin on purpose: the
template ships authentication end to end, and of the example catalogue only `Item` is a full
vertical slice — `Collection` and `Tag` are still ORM models alone.

```
backend/
├── src/
│   ├── domain/                    # CORE — pure business logic, no external dependencies
│   │   ├── models/                # Domain entities (dataclasses)
│   │   │   ├── user.py
│   │   │   └── example/item.py    # Item — the example catalogue's hub resource
│   │   ├── ports/                 # Interfaces (Protocol classes) exposed by the domain
│   │   │   ├── repositories.py    # Persistence ports (UserRepository)
│   │   │   ├── services.py        # External service ports (PasswordHasher, TokenService)
│   │   │   └── example/repositories.py       # ItemRepository
│   │   ├── services/              # Use cases / business logic
│   │   │   ├── auth_service.py
│   │   │   └── example/item_service.py       # Item use cases + the authorization matrix
│   │   └── exceptions.py          # Domain exceptions (UnauthorizedError, ForbiddenError, ...)
│   │
│   ├── adapters/                  # ADAPTERS — concrete implementations of the ports
│   │   ├── inbound/               # Inbound adapters (how the world calls the domain)
│   │   │   ├── api/               # FastAPI routes
│   │   │   │   ├── auth_router.py
│   │   │   │   ├── health_router.py
│   │   │   │   └── example/item_router.py    # /items — listing, search and CRUD
│   │   │   ├── schemas/           # Pydantic schemas (API request/response)
│   │   │   │   ├── auth_schemas.py
│   │   │   │   ├── common.py      # Generic ApiResponse + error_responses()
│   │   │   │   └── example/item_schemas.py   # One schema per operation
│   │   │   └── middleware/
│   │   │       ├── auth.py                # NOT middleware: the get_current_user dependency
│   │   │       ├── logging.py             # RequestLoggingMiddleware (request_id, duration_ms)

│   │   │

│   │       │   ├── user_repository.py
│   │       │   └── database.py                # Engine, session factory, get_db_session
│   │       ├── security/          # Implementations of the service ports
│   │       │   ├── password_hasher.py         # Implements PasswordHasher (bcrypt)
│   │       │   └── jwt_token_service.py       # Implements TokenService
│   │
│   ├── config/                    # Application configuration
│   │   ├── settings.py            # Pydantic Settings (env vars)
│   │   ├── logging.py             # configure_logging(): structlog + stdlib bridge
│   │   └── container.py           # Dependency injection (wiring ports → adapters)
│   │
│   └── main.py                    # FastAPI entrypoint, registers routers and middleware

│   ├── unit/                      # Domain services and pure adapters, with fakes
```

Everything belonging to the example catalogue lives in an `example/` folder **inside its own
layer**, never in one folder cutting across layers: the layer structure is the architecture, and
`example/` is only a removability marker inside it. The dependency runs example → template, never
the other way, which is why `ItemORM` points at `users` with a bare foreign key and no
`relationship()`. Removing the sample domain is a `rm -rf` of those folders plus the marked import
in `alembic/env.py`, the `include_router` in `main.py` and the two providers in `container.py` —
the full list is at the end of `docs/adding-a-feature.md`.

Note: `.pre-commit-config.yaml` lives at the **monorepo root** (git hooks are per-repository); the backend hooks filter with `files: ^backend/`.

## Hexagonal Architecture rules

1. **The domain does NOT import from adapters.** Ever. Imports always flow inward:
   - `adapters.inbound.api` → imports from `domain.services` and `domain.models`
   - `adapters.outbound.persistence` → imports from `domain.ports` and implements its interfaces
   - `domain.services` → imports from `domain.ports` and `domain.models`, NOTHING else

2. **Ports are Protocol classes** (typing.Protocol), not abstract classes:
   ```python
   from typing import Protocol


   class ItemRepository(Protocol):
       async def find_by_id(self, item_id: int) -> Item | None: ...
       async def find_all(self, skip: int, limit: int) -> list[Item]: ...
       async def save(self, item: Item) -> Item: ...
       async def delete(self, item_id: int) -> None: ...
   ```

3. **Domain models are independent of SQLAlchemy.** Use dataclasses or Pydantic BaseModel for the domain. SQLAlchemy models live in `adapters/outbound/persistence/` — `sqlalchemy_models.py` for the template's own tables, the `example/` package for the sample catalogue — and are mapped to and from the domain models.

4. **Dependency injection in `config/container.py`.** It wires the ports to their concrete implementations. Routers receive the domain services already injected via FastAPI Depends.

5. **Domain exceptions are translated in the error_handler middleware.** `UnauthorizedError` and `InvalidCredentialsError` → HTTP 401, `ForbiddenError` → HTTP 403, `ItemNotFoundError` → HTTP 404, `DuplicateEmailError` and `DuplicateSlugError` → HTTP 409. A new exception must add its entry to `_STATUS_CODES`, or it falls through to the default 500.

## Code conventions

- snake_case for everything (variables, functions, files, modules)
- PascalCase only for classes (models, schemas, exceptions, protocols)
- Async/await in every endpoint, service and repository
- Type hints mandatory on all functions (mypy strict)
- Docstrings on domain services and complex functions
- API responses always in this format:
  ```json
  {"success": true, "data": {...}, "error": null}
  {"success": false, "data": null, "error": "Item 42 not found"}
  ```
- Pydantic schemas split per operation: `ItemCreate`, `ItemUpdate`, `ItemResponse`, `ItemListResponse`

## Testing

- Framework: pytest + pytest-asyncio + httpx.AsyncClient
- AAA pattern: Arrange → Act → Assert (with comments)
- Fixtures centralized in `conftest.py`: DB session inside a rolled-back transaction, async client, and an `authenticated_as` helper that overrides `get_current_user`
- Unit tests: hand-written in-memory fakes for the ports (never mocks), domain services in isolation
- Integration tests: use a real test DB, verify the repositories
- API tests: httpx.AsyncClient against the FastAPI app
- Minimum coverage: 80% — enforced, not advisory. The gate lives in
  `pyproject.toml`: `[tool.coverage.run]` measures `src/` only (excluding
  `alembic/` and `seed.py`) and `[tool.coverage.report] fail_under = 80`
  makes any `--cov` run exit non-zero below the threshold. CI relies on that
  config instead of passing `--cov-fail-under` on the command line, so local
  and CI fail identically. Never lower it — add tests.
- Run: `pytest --cov=src --cov-report=term-missing`

## Migrations

- Alembic with autogenerate from the SQLAlchemy models (not from the domain models). `alembic/env.py` imports the `example` package so its tables are registered on `Base.metadata` and autogenerate does not propose dropping them
- Create a migration: `alembic revision --autogenerate -m "description"`
- Apply: `alembic upgrade head`
- Rollback: `alembic downgrade -1`
- Always review the generated SQL before applying it

## Logging

- structlog, configured in `src/config/logging.py`. Console rendering when `ENVIRONMENT` is a
  development alias (`development`, `dev`, `local`), JSON everywhere else. Output goes to stdout and
  nowhere else — there is no log file
- `RequestLoggingMiddleware` emits one `http_request` event per request with `method`, `path`,
  `status_code`, `duration_ms` and `request_id`, and returns the id in the `X-Request-ID` header
- The `request_id` travels through structlog contextvars, so every line of the request carries it
  automatically. Never pass it as a function argument
- There is **no** automatic `user_id` field: the user is resolved by the `get_current_user`
  dependency, which an outer middleware cannot see without duplicating the JWT logic
- Never use `print()` — always `logger.info()`, `logger.error()`, etc.

**Read `docs/backend-logging.md` before adding a log line or touching the middleware.**

## Linting

- Ruff as the single linter and formatter
- mypy in strict mode
- Pre-commit hooks: ruff check, ruff format, mypy

## What NOT to do

- Do not import SQLAlchemy, FastAPI, httpx or any infrastructure library inside `domain/`
- Do not put business logic in the routers — routers only validate input, call the service, and return the response
- Do not use `from sqlalchemy import ...` in `domain/services/`
- Do not create endpoints without their corresponding Pydantic schema
- Do not write direct SQL queries — always go through the repository
